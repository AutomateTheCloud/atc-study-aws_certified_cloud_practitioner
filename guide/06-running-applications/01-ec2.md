# Amazon EC2 rents you virtual servers: you pick the image, and you pick the instance type by what your work runs out of first

Amazon EC2 gives you a virtual server in minutes. You choose what runs on it (an image) and how much hardware it gets (an instance type), and the exam asks you to match a workload to an instance family.

**Exam guide:** [Domain 2, Security and Compliance](https://docs.aws.amazon.com/aws-certification/latest/cloud-practitioner-02/cloud-practitioner-02-domain2.html) (30% of the exam): task [2.1](https://docs.aws.amazon.com/aws-certification/latest/cloud-practitioner-02/cloud-practitioner-02-domain2.html#cloud-practitioner-02-task2.1); [Domain 3, Cloud Technology and Services](https://docs.aws.amazon.com/aws-certification/latest/cloud-practitioner-02/cloud-practitioner-02-domain3.html) (34% of the exam): task [3.3](https://docs.aws.amazon.com/aws-certification/latest/cloud-practitioner-02/cloud-practitioner-02-domain3.html#cloud-practitioner-02-task3.3); [Domain 4, Billing, Pricing, and Support](https://docs.aws.amazon.com/aws-certification/latest/cloud-practitioner-02/cloud-practitioner-02-domain4.html) (12% of the exam): task [4.1](https://docs.aws.amazon.com/aws-certification/latest/cloud-practitioner-02/cloud-practitioner-02-domain4.html#cloud-practitioner-02-task4.1).

## What you'll learn

Guess before you read on: an analytics program loads a large data set into memory and keeps running out of it. Which kind of instance helps?

## An instance is a virtual server started from an image

**Amazon Elastic Compute Cloud (Amazon EC2)** rents you virtual servers, called **instances**, and you pay while they run ([What is Amazon EC2?](https://docs.aws.amazon.com/AWSEC2/latest/UserGuide/concepts.html)). You start every instance from an **Amazon Machine Image (AMI)**, a template holding the operating system and any preinstalled software. Ten instances started from one AMI are identical, which is how Auto Scaling adds servers in the next lesson. At launch you also choose an **instance type**, storage, a network and security group, and how you'll sign in.

EC2 puts more on your side of the line than any other compute service ([Shared Responsibility Model](https://aws.amazon.com/compliance/shared-responsibility-model/)). AWS looks after the building, the hardware and the virtualization. You patch the guest operating system and its software, and you own the security group rules, sign-in, encryption, backups and running in more than one AZ.

## Choose the family from the bottleneck

An **instance type** is a named size of hardware, such as `m7g.large`. Every type has a balance of processor, memory, storage and network, and AWS groups the types into **instance families** by that balance ([Amazon EC2 instance types](https://docs.aws.amazon.com/ec2/latest/instancetypes/instance-types.html)). (Strictly, AWS's family is the part of the name before the dot, such as `m7g`, grouped into categories such as "memory optimized"; the exam guide calls the categories instance types.) To choose, find the workload's **bottleneck**, the resource it runs out of first, and the family follows.

![Six cards: general purpose, compute optimized, memory optimized, storage optimized, accelerated computing and HPC optimized, each with what runs out first, its letters and AWS's example workloads.](../../images/06-01-families.svg)

*Notice that "general purpose" is the answer when nothing in particular runs out.*

This table is the long description of the graphic (examples from the [EC2 instance types page](https://aws.amazon.com/ec2/instance-types/), checked 2026-10-23):

| Family | Runs out first | Letters | AWS's example workloads |
|---|---|---|---|
| General purpose | Nothing in particular: a balance | M, T | Web servers, code repositories, small and medium databases |
| Compute optimized | Processor (CPU) | C | Batch processing, media transcoding, dedicated game servers |
| Memory optimized | Memory | R, X, U, z1d | In-memory databases, analytics on large data sets in memory |
| Storage optimized | Fast reads and writes to local disks | I, D, H | High-throughput databases, data processing and streaming |
| Accelerated computing | Work for GPUs or other special chips | P, G, Inf, Trn | Machine learning, graphics, floating-point calculations |
| HPC optimized | Very large, tightly linked computations | Hpc | Complex simulations, deep learning, visual effects |

Two families need a closer look:

- **Burstable (T) instances** run at a baseline level of processor use and burst above it using credits earned when quiet. They suit web servers and test systems that sit idle most of the time.
- **Storage optimized means heavy, fast use of the instance's own local disks, not just more space** ([Storage optimized instances](https://docs.aws.amazon.com/ec2/latest/instancetypes/so.html)). If you only need more space, attach a bigger EBS volume or use S3 (Module 05).

> **Example:** ask of each of the bakery's jobs *what will it run out of first?* The web server, busy at lunch but never heavy for long: **general purpose, burstable**, such as a `t3.small`. The nightly photo resize, processor busy all run: **compute optimized**. The accountant's analysis, a year of sales in memory: **memory optimized**. A model that tags cake photos, trained on special chips: **accelerated computing**. Bottleneck first, family second, size last.

> **Your turn:** A video company converts uploaded films into formats for phones and TVs. Its servers' processors run at full speed for hours. Which family fits: memory optimized, storage optimized, compute optimized or general purpose?

<details><summary>Model answer</summary>

**Compute optimized.** Media transcoding keeps the processors busy, and AWS lists it as a compute optimized workload. Nothing here runs out of memory or local disk speed, and the load isn't balanced.

</details>

## Instance types are not purchasing options

Some study material calls On-Demand, Reserved and Spot EC2 instance types. They aren't. An instance type is hardware; a **purchasing option** is how you pay for that hardware ([Billing and purchasing options](https://docs.aws.amazon.com/AWSEC2/latest/UserGuide/instance-purchasing-options.html)). The mix-up has an official source: a list in the CLF-C02 exam guide calls these "instance types", so a question may use either meaning. Read such a question as being about how you pay (task [4.1](https://docs.aws.amazon.com/aws-certification/latest/cloud-practitioner-02/cloud-practitioner-02-domain4.html#cloud-practitioner-02-task4.1)).

The same `m7g.large` can be paid for in any of these ways:

| Purchasing option | What you commit to | Suits |
|---|---|---|
| **On-Demand** | Nothing; for Linux, billed by the second with a 60-second minimum | Short or unpredictable work |
| **Savings Plans** | A dollar amount per hour for 1 or 3 years | Steady spending that may change shape |
| **Reserved Instances** | One instance configuration for 1 or 3 years | Steady use of the same type |
| **Spot Instances** | Nothing, but AWS can reclaim the instance with a two-minute warning | Flexible work that can be interrupted |

A question can need both: the bottleneck picks the family, and how steady or interruptible the work is picks the way to pay (Module 11).

## Stopping pauses the instance bill; terminating ends it

**Stopping** an instance shuts it down so you can start it again later. **Terminating** deletes it for good, along with its instance store data and any volumes set to delete on termination ([Terminate Amazon EC2 instances](https://docs.aws.amazon.com/AWSEC2/latest/UserGuide/terminating-instances.html)).

It's easy to assume that a stopped instance costs nothing. That's wrong: AWS stops charging for instance time but keeps charging for its EBS volumes ([Amazon EC2 FAQs](https://aws.amazon.com/ec2/faqs/)). The belief is tempting because the server is off and the largest charge stops, but the disk is still stored for you.

Public IPv4 addresses bill by the hour, in use or idle (as of 2026-10-24, [Amazon VPC pricing](https://aws.amazon.com/vpc/pricing/)). An instance's automatic address is released when you stop it; an **Elastic IP address**, a fixed public address you keep, is charged until you release it. [Lab 08](06-lab-08-launch-and-terminate-an-instance.md) shows each state.

## Summary

- **An AMI is a template** for identical instances. The guest operating system and everything above it are yours.
- **Choose the family from the bottleneck:** general purpose for balance, compute optimized for processor, memory optimized for memory, storage optimized for fast local disks, accelerated computing for GPUs and other chips, HPC for huge linked computations.
- **Instance types aren't purchasing options.** On-Demand, Savings Plans, Reserved and Spot are ways to pay for a type.
- **A stopped instance still costs money** for its EBS volumes and any Elastic IP. Terminating ends the charges.

## Practice

1. **A company runs an in-memory database that must hold 500 GiB of data in RAM. Which instance family fits best?**

   A. Compute optimized\
   B. Memory optimized\
   C. Storage optimized\
   D. Accelerated computing

   <details><summary>Feedback</summary>

   **B is right.** The bottleneck is memory, and AWS names in-memory databases as a memory optimized workload.

   - **A is wrong.** Compute optimized adds processor power, not memory.
   - **C is wrong.** Storage optimized gives fast local disks; the data must be in RAM.
   - **D is wrong.** Accelerated computing adds GPUs and other chips.

   </details>

2. **Which of these is an EC2 instance type?**

   A. Spot\
   B. `c7g.large`\
   C. Reserved\
   D. On-Demand

   <details><summary>Feedback</summary>

   **B is right.** `c7g.large` names hardware: a compute optimized type.

   - **A, C and D are wrong.** Spot, Reserved and On-Demand are purchasing options: ways to pay for an instance type.

   </details>

3. **An instance is stopped for 30 days. Which charges continue?**

   A. Instance time only\
   B. EBS volume storage, and any Elastic IP address kept\
   C. Nothing, because the instance is off\
   D. Instance time and EBS storage

   <details><summary>Feedback</summary>

   **B is right.** Stopping ends instance-time charges, but EBS volumes are billed while they exist, and an Elastic IP is billed until released.

   - **A and D are wrong.** No instance time is billed while stopped.
   - **C is wrong.** That's the misconception: the disk is still stored for you.

   </details>
